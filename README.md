Орчин: Linux (Debian). Тестийн хэрэгсэл: Postman collection (v2.1) ба Newman. Collection-д `baseUrl` = `http://localhost:3000`.

## 1. Сонголт ба төлөөлөх утгын хүснэгт

| Сонголт | Эквивалент анги (төлөөлөх утга) |
| --- | --- |
| studentID | идэвхтэй (`"status":"active"`) · идэвхгүй (`"status":"inactive"`) · байхгүй (PUT хийгээгүй ID) |
| Оюутны үзсэн хичээл | урьдачийг бүгдийг хангана · зарим нь дутуу · огт үзээгүй (`[]`) |
| courseID | байгаа (PUT хийсэн) · байхгүй |
| Хичээлийн урьдач | урьдачгүй (`[]`) · нэг урьдачтай (`["CS201"]`) · хоёр урьдачтай (`["CS201","CS202"]`) |
| Хүсэлтийн формат | бүрэн JSON · studentID дутуу · courseID дутуу · буруу JSON |
| Уншилтын хүсэлт | GET /courses/:id (байгаа / байхгүй) · GET /registrations |

## 2. Спецификацийн хүснэгт

| № | Оролт | Статус | result |
| --- | --- | --- | --- |
| T01 | Идэвхтэй оюутан (CS201 үзсэн), CS201 урьдачтай хичээл | 201 | `OK` + registrationID (тоо) |
| T02 | Оюутан байхгүй, хичээл байгаа | 200 | `ERROR_NO_STUDENT` |
| T03 | Идэвхгүй оюутан, хичээл байгаа | 200 | `ERROR_INACTIVE_STUDENT` |
| T04 | Идэвхтэй оюутан, хичээл байхгүй | 200 | `ERROR_NO_COURSE` |
| T05 | Урьдач огт үзээгүй | 200 | `ERROR_PREREQUISITES`, missing=`["CS201"]` |
| T06 | Урьдачийн зарим нь дутуу (CS201 үзсэн, CS202 үзээгүй) | 200 | `ERROR_PREREQUISITES`, missing=`["CS202"]` |
| T07 | Хязгаар: урьдачгүй хичээл, хоосон coursesTaken | 201 | `OK` |
| T08 | Хязгаар: courseID дутуу | 400 | `ERROR_BAD_REQUEST` |
| T09 | Хязгаар: studentID дутуу | 400 | `ERROR_BAD_REQUEST` |
| T10 | Буруу JSON бие | 400 | `ERROR_BAD_JSON` |
| T11 | Давхар алдаа: оюутан ч, хичээл ч байхгүй | 200 | `ERROR_NO_STUDENT` |
| T12 | Давхар алдаа: идэвхгүй оюутан + хичээл байхгүй | 200 | `ERROR_INACTIVE_STUDENT` |
| T13 | Давхар алдаа: идэвхгүй оюутан + урьдач дутуу | 200 | `ERROR_INACTIVE_STUDENT` |
| T14 | GET /courses/:id: байгаа хичээл / байхгүй хичээл | 200 / 404 | prerequisites=`["CS201"]` / — |
| T15 | Амжилттай бүртгэл GET /registrations жагсаалтад орно | 201, дараа нь 200 | `OK`, жагсаалтад таарах бичлэг |

Давхар алдааны T11–T13-ын хүлээгдэх утгыг заавар заагаагүй тул тестийг серверт ажиллуулж ажигласан дарааллаар тогтоосон. Ажиглалтын дүн: оюутан байхгүй бол `ERROR_NO_STUDENT`, идэвхгүй оюутан бол хичээл байхгүй эсвэл урьдач дутуу байсан ч `ERROR_INACTIVE_STUDENT` буцдаг. Тиймээс оюутны шалгалт хичээлийнхээс түрүүлж хийгддэг.

Тест бүр өөрийн ID-тай (`T01_stu`, `T01_crs` ...) өөрийн setup PUT-аа хийдэг. registrationID-ийн яг утгыг шалгаагүй, зөвхөн `number` төрлийг шалгасан. T15-д POST-оос ирсэн ID жагсаалтад байгаа эсэхийг шалгана.

## 3. Newman-ийн үр дүн

| Ажиллуулалт | Файл | Collection | assertions executed | failed | Exit code |
| --- | --- | --- | --- | --- | --- |
| PASS | `results/newman-pass.txt` | `lab05-collection.json` | **53** | 0 | 0 |
| FAIL | `results/newman-fail.txt` | `lab05-collection-fail.json` | 53 | 1 | 1 |
| DOWN | `results/newman-down.txt` | `lab05-collection.json` (сервер унтраасан) | 53 | 53 | 1 |

Collection: 15 folder (тест), 35 хүсэлт, **53 assertion**. Үүнээс 18 нь setup PUT-ийн статус шалгалт, 35 нь oracle шалгалт.

- **FAIL:** T01-ийн oracle-ийг зориуд `201` биш `200` гэж хүлээлгэсэн. Newman: `Happy path: статус 200 ... expected response to have status code 200 but got 201`. Үндсэн collection зөв хэвээр.
- **DOWN:** `results/newman-down.txt`-д `ECONNREFUSED` мөр байна. Сервер хариу өгөөгүй тул oracle-ийг хэмжих хариу байгаагүй. Энэ нь oracle-ийн алдаа биш, интерфейсийн (холболтын) алдаа.
- Exit code-ийг `tee`-ийн дараа `${PIPESTATUS[0]}`-оор авсан (`$?` нь tee-ийн 0-г өгнө).

## 4. Дүгнэлт

Хамгийн их бодол шаардсан нь спецификаци байсан, учир нь нэг хүсэлтэд хэд хэдэн алдаа зэрэг байвал аль нь буцахыг заавар заагаагүй. T11–T13-ыг ажиллуулж үзэхэд сервер оюутны шалгалтыг хичээлийнхээс түрүүлж хийдэг нь тогтсон: оюутан байхгүй бол ERROR_NO_STUDENT, идэвхгүй оюутан бол хичээл байхгүй эсвэл урьдач дутуу байсан ч ERROR_INACTIVE_STUDENT буцна. Тест бүр өөрийн ID-тай (T01_stu, T01_crs гэх мэт), өөрийн setup PUT-тай тул бие даасан бөгөөд сервер дахин асаахгүйгээр олон удаа ажиллуулахад тэнцсэн. Сервер санах ойд хадгалдаг тул registrationID-ийн утгыг шалгаагүй, зөвхөн number төрлийг нь шалгасан. Хуулбарласан T05-д T01, T02-ийн ID үлдсэн байсан бөгөөд тест ногоон гарч байсан ч өөр тестийн өгөгдөл ашиглаж байсныг Postman-ий Run үр дүнгээс URL-ыг нь хараад олж засав. Мөн export хийсэн collection-д baseUrl хоосон гарч Newman "Invalid URI" алдаа өгсөн. FAIL ба DOWN ажиллуулалт хоёулаа exit code 1 өгдөг ч утга нь өөр: FAIL үед сервер хариу өгсөн боловч oracle таараагүй (T01-д 200 хүлээсэн, 201 ирсэн, 53-аас 1 унасан), DOWN үед хариу огт ирээгүй (ECONNREFUSED) тул 53 бүгд унасан бөгөөд энэ нь интерфейсийн алдаа. Иймд exit code-оор хоёрыг ялгах боломжгүй, тайланг уншиж ялгана. Тестүүд серверийн согог илрүүлсэнгүй. Гэхдээ давхар алдааны дарааллыг серверийн одоогийн үйлдлээс тогтоосон тул тест нь тэр үйлдлийг түгжиж байгаа бөгөөд зохиогчийн зорилгод нийцэж байгааг батлахгүй.
